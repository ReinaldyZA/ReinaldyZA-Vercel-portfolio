LayanKita user manuals: web dashboard and mobile app

Two guides. I wrote the 28-page manual for the web dashboard. The 131-page manual for the mobile app came from the developer team, and I anonymized it for this portfolio.

My role
Author of the web manual. Anonymized the mobile manual
Scope
Web dashboard and Android app
Context
Internship project. App, company, client, places and people are anonymized
Date
Internship Feb 2025 to Feb 2026. Rewritten for portfolio Nov 2026
Tools
Word
Deliverables
28-page web manual, 131-page mobile manual

The question

Can a new admin, or a resident, use LayanKita on day one without asking anyone?

Background

Admins and staff were trained before release, and the manuals are what they keep afterwards. Where the mobile manual differs from the app, for example the hotel booking flow and barcode tickets, the difference is recorded in section 9.2 of the mobile SRS.

Method

  1. Listed the device requirements for the web dashboard, such as a recent browser and a screen at least 1280 pixels wide.
  2. Wrote one chapter per dashboard menu, in the order an admin uses them, with numbered steps and a screenshot for every task.
  3. Closed the web manual with common problems and how to solve them.
  4. Anonymized the developer team's mobile manual without changing its content, and checked it against the app.

What is inside

  • Web manual, written by me. 28 pages in 11 chapters, from getting started to complaints, content, tickets and regional data.
  • Mobile manual, by the developer team. 131 pages covering every app menu, from onboarding and the home screen to complaints, tickets and attendance.
  • Screenshots. Every menu is shown as it appears on screen.
  • Known gaps. Differences between the mobile manual and the app are listed in the mobile SRS.
