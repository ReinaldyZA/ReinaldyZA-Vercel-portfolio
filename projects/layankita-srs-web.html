LayanKita SRS, web dashboard: 48 functional requirements

The software requirements specification for the admin dashboard: roles and access, functional and non-functional requirements, use cases and ERDs.

My role
System Analyst intern, author
Scope
Admin dashboard, 4 staff roles
Context
Internship project. App, company, client, places and people are anonymized
Date
Internship Feb 2025 to Feb 2026. Rewritten for portfolio Nov 2026
Method
MoSCoW priority per requirement
Deliverables
19-page SRS

The question

Exactly what must the admin dashboard do, for which role, and under what rules?

Background

The dashboard is where admins, health facility staff, ticket counter staff and developers follow up complaints and manage content. This SRS starts from BRD version 1.0 and from observing the dashboard as an admin.

Method

  1. Defined the roles and what each one can open.
  2. Wrote 48 functional requirements, each with a rule, a MoSCoW priority and an agreement status.
  3. Added 17 non-functional requirements for security, performance and data quality.
  4. Added use cases and ERDs, and marked which requirements were still proposals until the client approved version 1.0.

What is inside

  • 48 functional requirements. From login and role checks to complaints, content, events, sports and regional data.
  • 17 non-functional requirements. For example, an account locks for 15 minutes after 5 failed logins.
  • Agreement status. Every requirement says whether it is agreed or still needs confirmation.
  • Use cases and ERDs. So developers see the flow and the data together.
