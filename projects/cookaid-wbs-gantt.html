Cookaid WBS and Gantt chart: six phases in a 20-week plan

The question

What are all the pieces of work, and in what order can they happen?

Background

A WBS answers what needs to be done. A Gantt chart answers when. Doing the breakdown first showed which work could run in parallel, such as the frontend review running alongside the API and UI reviews.

Method

  1. Broke the project into six phases: initiation, design and planning, development, testing, deployment, and post-launch.
  2. Split each phase into work packages, down to single features such as Sign In and Video Tutorial.
  3. Placed nine milestones on a weekly timeline from 15 October 2024 to 1 March 2025.
  4. Let the frontend review overlap the API and UI reviews, then ran testing and release one after another.

What is inside

  • 6 phases, 40+ work packages. From drafting the PRD to post-launch optimization.
  • 20 weeks. 15 October 2024 to 1 March 2025.
  • Parallel work. The frontend review runs from 2 November to 15 December, alongside other reviews.
  • Testing before release. Functional, integration and user acceptance testing, then a whitelist release and public launch.
